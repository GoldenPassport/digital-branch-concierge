Now build the agent's skills and tools as server actions and attach them to the agent (CallTrialClaudeHaiku4_5) as actions it can call. Follow OutSystems best practice for agent actions: clear names, descriptions and parameter descriptions, because the model chooses actions from them. Use entity actions and aggregates only, no SQL nodes. Do not create screens or timers.

Identity rule: the identified customer must come from the process, never from the model. Add an entity ConciergeSession (SessionId Text 50, CustomerId Text 10, PolicyRequested Boolean, CreatedOn DateTime). CallBranchConcierge gets a new input CustomerId; at its start, create or update ConciergeSession for the SessionId. Every skill reads the session's customer from ConciergeSession. Pass SessionId to every agent action as a bound (static) parameter, not one generated by AI.

1) Server action Authorise(CapabilityName, SessionId, AccountId optional) returns IsAuthorised (Boolean), Reason (Text), Risk (Text). Rules, in order: capability not in the Capability entity -> not authorised, risk high, reason "<name> is not an allowed skill or tool."; Kind = tool -> authorised, reason "Read-only lookup."; no ConciergeSession or customer for SessionId -> not authorised, reason "No identified customer in this session. Identification happens before any account action."; AccountId given and it does not belong to the session customer -> not authorised, reason "The account does not belong to the identified customer."; otherwise authorised, reason "Within policy for this customer." Risk always comes from the Capability entity. Every call writes a DecisionLog row (Step "authorise").

2) Every skill returns a JSON text result {"skill": name, "risk": risk, "status": "done" or "refused", "result": text}. On refusal the result is "Refused: " + reason. Each skill calls Authorise first and stops if refused.
- print_statement(AccountId, PeriodMonths default 3, 1 to 24): "Print a statement for the customer's own account. Risk: low, read only." Result: "Statement printed for <account> covering <start date> to <today> (<n> months). Stamped copy handed to the customer at the concierge desk. Reference STM-<6 random uppercase hex>."
- fetch_balance(AccountId): "Fetch the available balance on the customer's own account. Risk: low, read only." Result: "Available balance on <account>: £<balance with 2 decimals, minus sign before £ if negative>."
- book_appointment(AppointmentType, PreferredTime optional): "Book a 45-minute branch appointment. Risk: low, reversible." Insert an Appointment row. Result: "Booked: <type> appointment, <PreferredTime or next available slot>, 45 minutes. Reference APT-<6 hex>. The customer can cancel or move it at any time."
- update_contact_details(Field phone or email, NewValue): "Update the customer's phone or email. Risk: medium, writes data. A named decision owner approves before it runs, so tell the customer it may take a moment." Validate NewValue (email pattern, or phone with at least 7 digits); invalid -> refused "'<value>' is not a valid <field>. Ask the customer to check it." Valid -> insert ContactChangeRequest with Status pending and do NOT change the Customer record. Result: "Change of <field> to <value> is waiting for approval by a member of staff. Reference CCR-<6 hex>."

3) Read-only tools (still call Authorise, which returns authorised for tools), plain text results:
- knowledge(Query): "Search the bank's own documents: fees and product terms, opening hours, what to bring, appointments, complaints policy, what the concierge may and may not do. Input: a short search phrase. Returns the most relevant sections. Use it before answering any policy or product question." Split the query (lower case) into words on any non-letter or non-digit character and keep words longer than 2 letters; for each KnowledgeSection count how many of those words appear anywhere in lower case Document + Heading + Body; return the top 3 sections with a count above 0 as "[<Document> / <Heading>]", a new line and the Body, separated by blank lines; if none match: "No matching section in the bank documents. Say so rather than guessing." Do not search for the whole query as one phrase.
- opening_hours(Day default today): Monday to Friday 09:00 to 17:00, Saturday 09:00 to 13:00, Sunday closed. Result "<Day>: <hours>. Closed on bank holidays."
- find_slots(AppointmentType default general): "Read-only lookup of the next available appointment slots. Booking is a separate skill." Result "Next <type> slots: <tomorrow> 14:00, <tomorrow> 15:30, <day after> 10:00. Each slot is 45 minutes."

Set the agent's Call Condition to TotalCallsCount >= 6 (when it is true the agent stops calling actions).
