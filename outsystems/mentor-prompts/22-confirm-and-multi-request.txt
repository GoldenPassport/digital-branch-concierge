Rejected and sent-back keep today's behaviour, then end with the closing question.

2) Carrying it out after the customer confirms. In RunAgent, when the session's case has a review round with ExecutionStatus "awaiting_confirmation", add it to the agent's context ("Approved by <DecidedBy>, waiting for the customer to confirm: <capability> <details>"). After either, the reply ends with the closing question.

3) Question types. Every agent turn sets QuestionType: "confirm" (go ahead with an approved action?), "closing" (anything else I can help you with?), "needs_info" (the agent needs an answer), or "none". Add QuestionType (Text 20) to ConciergeReply and return it from ListReplies so the chat can show buttons. Keep the existing "anything else" detection as a fallback.

4) Triage: switch ClassifyReply and CheckReply from structured output (DeepSeek rejects response_format json_schema) to Text output with a JSON instruction and an example, then take the text from the first "{" to the last "}", deserialize, and validate; on failure log a Warning with the raw text and use the fallback below. ClassifyReply classifications: "continue" (an answer, a confirmation, a "yes", or a new request: all stay in the same case) and "done" (no, that's all, thanks, goodbye). Fallback rule: "done" if the reply is under 40 characters and starts with no / no thanks / that's all / that's everything / thanks / nothing else, otherwise "continue". Write CaseEvent "Reply triaged" (Actor "Triage", Detail = classification + " · " + reason). Remove the rule that a new request closes the case and starts a new one.

5) Timeouts: when CloseCustomerWait runs while a round is "awaiting_confirmation", set ExecutionStatus "expired" and close the case with Outcome "not_confirmed" (CaseEvent title "No confirmation from the customer"); otherwise as today.

6) Summaries: SummariseCustomerCase must summarise every request in the case, not only the first (e.g. "Saturday hours; account closure approved and confirmed").
